# Web Importer UI Redesign — Design Spec

วันที่: 2026-10-10 · สถานะ: รอผู้ใช้ตรวจ

## เป้าหมาย

ออกแบบหน้าเว็บใหม่ทั้งหมดโดยเน้นการใช้งาน: จากเปิดหน้าจนเริ่มดึงช่วงตอนที่ต้องการต้องไม่ต้องเลื่อนหาปุ่ม, ทุกปุ่มของขั้นตอนปัจจุบันมองเห็นได้ตลอด และแก้บัคปุ่ม "เริ่มดึงเนื้อหา" ที่กดไม่ได้หลังดึงสารบัญเสร็จ

### เกณฑ์ความสำเร็จ

- หลังดึงสารบัญเสร็จ ปุ่มเริ่มดึงกดได้ทันทีโดยไม่ต้องคลิกอะไรก่อน
- ที่ viewport 1280×800 รายการตอน, การตั้งค่า, ความคืบหน้า และปุ่มทั้งหมดของแท็บดึงจากเว็บอยู่ในจอเดียว (เลื่อนเฉพาะภายในรายการตอน)
- เลือกช่วง เช่น 101–200 ได้ด้วยการพิมพ์ตัวเลขสองช่อง
- ลองดึงเฉพาะตอนที่ล้มเหลวหรือถูกหยุดได้ด้วยปุ่มเดียว โดยตอนที่สำเร็จแล้วยังอยู่ครบ
- ความสามารถเดิมทั้งหมดยังใช้ได้ ยกเว้นที่ระบุว่าแทนที่หรือนำออกในหัวข้อ "สิ่งที่นำออก"

### ข้อจำกัดและสมมติฐาน

- ใช้งานบน desktop ในเครื่องเดียวกับ server (bind 127.0.0.1) แต่ต้องไม่พังที่จอแคบ
- คง HTML/CSS/JS ล้วน ไม่มี framework หรือ build step
- Backend, API (`/api/toc`, `/api/chapter`) และรูปแบบไฟล์ export ไม่เปลี่ยน
- UI ภาษาไทย

### นอกขอบเขต

ค้นหาชื่อตอน, จำค่าที่ตั้งไว้ใน localStorage, แบ่งชุดดึงอัตโนมัติ, ตัด URL ซ้ำในสารบัญ, ดึงตอนที่สำเร็จแล้วซ้ำ, การเปลี่ยนแปลงฝั่ง server

## 1. Layout

### โครงหน้า

```
┌ Web Importer ───────────────────────── ● FlareSolverr: เชื่อมต่อแล้ว ┐
│ [ดึงจากเว็บ 45/100]  [จัดการไฟล์ .txt]                               │
├──────────────────────────────────────────────────────────────────────┤
│ URL สารบัญ [______________________________________] [ดึงสารบัญ]       │
│ (ข้อความ error บรรทัดเดียว)                                            │
├────────────────────────────────────────────┬─────────────────────────┤
│ [เลือกทั้งหมด] ช่วง [101]–[200] [เลือกช่วง]  │ เลือก 100 จาก 240 ตอน   │
│ เริ่มเลขที่ # [1]  [⇅ สลับลำดับ]             │ หน่วง [100] ms           │
├────────────────────────────────────────────┤ พร้อมกัน [4]             │
│ ☑ #101 第101章 ชื่อตอน        ✓ สำเร็จ      │ ▓▓▓▓▓▓░░░░ 45 / 100      │
│        example.com/chapter/101             │ สำเร็จ 44 · ล้มเหลว 1    │
│ ☑ #102 第102章 ชื่อตอน        ⟳ กำลังดึง    │ [ หยุด ]                 │
│ ☐ #103 ...                                 │ [ ลองดึงตอนที่ไม่สำเร็จ (1) ] │
│   (เลื่อนเฉพาะรายการ)                        │ [ ดาวน์โหลด .txt (44 ตอน) ] │
│                                            │ [ เริ่มใหม่ ]             │
└────────────────────────────────────────────┴─────────────────────────┘
```

### ส่วนประกอบ

- **แถบบน**: ชื่อ "Web Importer" แบบกระชับ, ป้ายสถานะ FlareSolverr (รอการเชื่อมต่อ / กำลังเชื่อมต่อ / เชื่อมต่อแล้ว / เกิดข้อผิดพลาด) และแท็บ
- **แท็บ** (`role="tablist"`): `ดึงจากเว็บ` และ `จัดการไฟล์ .txt` สลับด้วยคลิกหรือปุ่มลูกศรซ้าย/ขวา ระหว่างกำลังดึง แท็บดึงจากเว็บแสดงตัวนับ เช่น `45/100` การสลับแท็บไม่หยุดงานที่ดึงอยู่
- **แถว URL**: ช่อง URL + ปุ่ม `ดึงสารบัญ` และพื้นที่ข้อความ error เพียงจุดเดียว (`role="alert"`)
- **ฝั่งซ้าย — รายการตอน**
  - Toolbar: `เลือกทั้งหมด`/`ยกเลิกทั้งหมด`, ช่วง `[จาก]–[ถึง]` + `เลือกช่วง`, `เริ่มเลขที่ #`, `สลับลำดับ`
  - รายการเลื่อนในกล่องของตัวเอง ความสูงเติมพื้นที่ที่เหลือของจอ (ขั้นต่ำ 360px)
  - แต่ละแถว: checkbox จริง, `#เลข`, ชื่อตอน, URL ตัวเล็ก, ชิปสถานะ
  - ก่อนมีสารบัญ: แสดงวิธีใช้ 3 ขั้นสั้นๆ แทนรายการ
- **ฝั่งขวา — แผงควบคุม (sticky)**: จำนวนที่เลือก, หน่วง (ms), พร้อมกัน, แถบความคืบหน้าพร้อมจำนวน สำเร็จ/ล้มเหลว/เหลือ, ปุ่มทั้งหมด
- **แท็บจัดการไฟล์ .txt**: ความสามารถและค่าเริ่มต้นเดิม (encoding, ช่วง 205–400) จัดเป็น 2 คอลัมน์ ซ้ายคือ input และปุ่ม ขวาคือสถานะและตัวอย่างผลลัพธ์
- **จอแคบ (< 900px)**: เรียงเป็นคอลัมน์เดียว แผงควบคุมอยู่เหนือรายการ รายการสูงไม่เกิน 60vh

### สไตล์

คงโทนมืดอุ่นเดิม (พื้นเข้ม, ตัวอักษรครีม, accent สีส้มอำพัน, สีเขียว/แดงสำหรับสำเร็จ/ล้มเหลว) แต่เรียบขึ้น: ไม่มีแสงเรือง, gradient พื้นหลัง หรือป้ายตกแต่ง ขนาดตัวอักษรหัวเรื่องพอดีกับงาน font stack เพิ่มฟอนต์จีนตัวเต็ม (`"Noto Sans TC", "Microsoft JhengHei"`) ต่อจาก `"Noto Sans Thai", Tahoma` ทุกปุ่มและ input มี focus ring ชัดเจน

### สิ่งที่นำออกหรือแทนที่

| เดิม | ใหม่ |
|---|---|
| Hero, Quick guide, footer, แสงเรืองพื้นหลัง | นำออก |
| ช่อง "เริ่มที่ Chapter #" สองจุด | เหลือจุดเดียวใน toolbar รายการ |
| ปุ่มเลือกเร็ว 1/5/10/…/100 ตอน | แทนด้วยการเลือกช่วง (เช่น 1–100) |
| ปุ่ม `ดาวน์โหลดทันที` และ `ดาวน์โหลดไฟล์ .txt` | รวมเป็นปุ่มเดียว |
| รายการความคืบหน้าแยกจากรายการตอน | สถานะแสดงในแถวของรายการตอนเลย |
| ข้อความ error สองจุด (บน/ล่าง) | จุดเดียวใต้ช่อง URL |

## 2. Behavior

### โมเดลข้อมูล

รายการตอนมีชุดเดียว แต่ละตอน:

```js
{ idx, title, url, chapterNumber, selected, status, content, error }
```

`status` เป็นหนึ่งใน `idle` (ยังไม่เคยดึง), `queued`, `fetching`, `done`, `error`, `stopped`

### การกระทำ

- **ดึงสารบัญ**: แทนที่รายการทั้งหมด ทุกตอนถูกเลือก สถานะ `idle` เลขตอนเริ่มจากค่า `เริ่มเลขที่ #` ถ้ามีตอนที่ดึงสำเร็จอยู่แล้ว ต้องยืนยันก่อน (`confirm`) เพราะเนื้อหาจะหายไป
- **เลือกแถว**: คลิกแถวหรือ checkbox เพื่อสลับ, Shift+คลิกเพื่อเลือก/ยกเลิกเป็นช่วงจากแถวที่คลิกล่าสุด
- **เลือกช่วง**: `จาก`/`ถึง` อ้างอิงเลข `#` ที่แสดง รวมทั้งสองปลาย และแทนที่การเลือกเดิม ข้อมูลไม่ถูกต้องให้แสดงข้อความ error และไม่เปลี่ยนการเลือก:
  - ไม่ใช่จำนวนเต็มบวก → `ช่วงตอนต้องเป็นจำนวนเต็มบวก`
  - จาก > ถึง → `ตอนเริ่มต้นต้องไม่มากกว่าตอนสิ้นสุด`
  - ไม่มีตอนในช่วง → `ไม่พบตอนในช่วง {จาก}–{ถึง}`
- **เริ่มเลขที่ # / สลับลำดับ**: คำนวณ `chapterNumber = start + index` ใหม่ทุกแถว
- **`เริ่มดึง N ตอน`**: ดึงตอนที่ `selected && status === "idle"` ตามลำดับรายการ ใช้ `runWithConcurrency` กับค่าหน่วงและพร้อมกันปัจจุบัน
- **`หยุด`**: แสดงแทนปุ่มเริ่มดึงขณะกำลังดึง ยกเลิกคิวและ request ที่ค้าง ตอนที่ `queued`/`fetching` กลายเป็น `stopped`
- **`ลองดึงตอนที่ไม่สำเร็จ (k)`**: แสดงเมื่อ k > 0 โดย k = ตอนที่ `selected && (status === "error" || status === "stopped")` ล้าง error แล้วดึงเฉพาะตอนเหล่านั้น
- **`ดาวน์โหลด .txt (n ตอน)`**: n = ตอนที่ `selected && status === "done"` export ตามลำดับรายการด้วย `buildExportText` เดิม ใช้ได้ระหว่างดึง ปิดเมื่อ n = 0
- **`เริ่มใหม่`**: หยุดงานที่ค้าง ล้างรายการและข้อความ คงข้อความในช่อง URL ไว้ ถ้ามีตอนที่สำเร็จต้องยืนยันก่อน ไม่กระทบแท็บไฟล์

### ระหว่างกำลังดึง

ล็อก checkbox, toolbar รายการ, ช่องหน่วง/พร้อมกัน และปุ่มดึงสารบัญ แต่ปุ่มหยุดและดาวน์โหลดยังใช้ได้

ส่วนความคืบหน้าในแผงควบคุมซ่อนอยู่จนกว่าจะเริ่มดึงรอบแรก จากนั้นแสดงของรอบล่าสุด: แถบและข้อความ `ทำเสร็จแล้ว / ทั้งหมดในรอบ`, จำนวนสำเร็จ · ล้มเหลว · หยุด และ "เหลือ" (= `queued` + `fetching`) ระหว่างดึง สรุปผลเมื่อจบรอบและประกาศผ่าน live region

### การแก้บัคปุ่มเริ่มดึง

สาเหตุ: `updateSelectionSummary()` ถูกเรียกขณะ `state.isBusy` ยังเป็น `true` และไม่ถูกเรียกอีกหลัง `finally` ปลดสถานะ

แก้ที่โครงสร้าง: สถานะ enabled/disabled, label และการแสดง/ซ่อนของทุกปุ่ม คำนวณจากฟังก์ชันบริสุทธิ์ `importerControls(state)` เพียงจุดเดียว และ `renderControls()` ถูกเรียกหลังการเปลี่ยน state ทุกครั้ง รวมถึงหลัง `finally` ของการดึงสารบัญและการดึงเนื้อหา แยก flag `tocLoading` กับ `running` แทน `isBusy` ตัวเดียว

### ประสิทธิภาพ

สร้าง DOM ของแถวใหม่ทั้งหมดเฉพาะตอนโหลดสารบัญหรือสลับลำดับ เก็บ `Map` จาก `idx` ไปยัง element ของแถว การเปลี่ยนสถานะระหว่างดึงอัปเดตเฉพาะแถวนั้น การเปลี่ยนการเลือกหรือเลขตอนอัปเดต checkbox/เลขในแถวเดิมโดยไม่สร้างใหม่

## 3. โครงสร้างโค้ดและการทดสอบ

### ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `public/index.html` | เขียนใหม่ตาม layout |
| `public/styles.css` | เขียนใหม่ รวมสไตล์ของแท็บไฟล์ไว้ด้วย |
| `public/file-tools.css` | ลบ |
| `public/app.js` | สลับแท็บ และเรียก `initImporter()`, `initFileTools()` |
| `public/importer.js` | DOM และ flow ของแท็บดึงจากเว็บ |
| `public/file-tools.js` | DOM และ flow ของแท็บไฟล์ (ย้ายจาก `app.js` เดิม พฤติกรรมเดิม) |
| `public/app-core.js` | ฟังก์ชันเดิม + ฟังก์ชันบริสุทธิ์ใหม่ด้านล่าง |
| `README.md` | อัปเดตขั้นตอนใช้งานตาม UI ใหม่ |

Dockerfile คัดลอกทั้งโฟลเดอร์ `public` อยู่แล้ว ไม่ต้องแก้

### ฟังก์ชันบริสุทธิ์ใหม่ใน `app-core.js`

- `selectChapterRange(chapters, from, to)` → คืนรายการใหม่ที่ `selected` ตรงกับช่วง หรือ throw `Error` ข้อความตามหัวข้อการเลือกช่วง
- `chaptersToStart(chapters)` → `selected && status === "idle"`
- `chaptersToRetry(chapters)` → `selected && status ∈ {error, stopped}`
- `exportableChapters(chapters)` → `selected && status === "done"` ตามลำดับรายการ
- `importerControls({ chapters, tocLoading, running })` → สถานะของ start/stop/retry/download/reset และตัวนับที่แผงควบคุมใช้

### การทดสอบ

- เขียน unit test ใน `test/client-core.test.js` ก่อนเขียนโค้ด (TDD) สำหรับทุกฟังก์ชันใหม่ รวมกรณีบัค: มีตอนที่เลือก, `tocLoading: false`, `running: false` → ปุ่มเริ่มดึงใช้ได้และนับจำนวนถูกต้อง
- อัปเดต `test/e2e.test.js` ให้ตรวจ id ใหม่ของ UI (แท็บ, `start-fetch-button`, `stop-button`, `retry-button`, `export-button`, ส่วนประกอบของแท็บไฟล์)
- `npm test` ต้องผ่านทั้งหมด
- ตรวจในเบราว์เซอร์จริงด้วย FlareSolverr จำลองที่ 1280×800 และ 390px: ดึงสารบัญ → ปุ่มเริ่มดึงใช้ได้ทันที → เลือกช่วง 101–200 → เริ่มดึง → หยุด → ลองดึงตอนที่ไม่สำเร็จ → ดาวน์โหลดได้ข้อความถูกต้อง → สลับแท็บระหว่างดึงแล้วงานยังเดิน → แท็บไฟล์จัดรูปแบบและดาวน์โหลดได้
